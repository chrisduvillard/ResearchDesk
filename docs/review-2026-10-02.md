# Repository and data review

**Reviewed:** 2 October 2026 · **Initial release:** 1.4.2

The original review below records version 1.4.2. The [version 1.5.0 follow-up](#data-availability-follow-up--version-150) updates its historical coverage and price findings.

## Result

The review found and fixed collection, interpretation, concurrency and display problems. Four missing official DBMF reports were recovered and imported. The release is deployed, both collectors work, and a restored production backup passes reconciliation with no discrepancies.

**The repository remains private.** Before publishing, use a fresh repository containing the cleaned history: GitHub still returns an unreachable commit from the old history containing a personal author/committer email. Rewriting the reachable branches and tags did not remove that cached object. No credentials were found in the reachable history.

The accepted data reconciles to its archived sources. Historical coverage remains incomplete, and malformed provider prices remain explicit gaps. This review does not establish the publishers' underlying figures independently or certify the application against every possible defect.

## Scope and method

- Reviewed application code, deterministic parsers and mappings, SQLite storage and migrations, collection/retry scheduling, options analysis, scoring, exports, browser state and charts, deployment configuration, dependency locks, documentation and repository screenshots.
- Scanned every reachable Git commit and tag for secrets; checked repository visibility, author metadata, ignored runtime files and dependency vulnerability reports.
- Took a consistent production backup before changes. Reparsed every accepted source archive, checked archive hashes and row counts, and compared stored fields with the source records.
- Independently recalculated every DBMF holding and market aggregate with decimal arithmetic, including long, short, net and gross exposure before netting.
- Downloaded the existing historical PDFs again: all 12 matched their archived bytes. Visually inspected the relevant pages of the four newly recovered reports and added extracted source fixtures.
- Checked every stored price bar for valid OHLC values and completion rules; reconciled all 15 price series to fresh provider downloads, including yen inversion. Checked equity/ETF exchange sessions within each series' coverage.
- Ran regression tests locally and in the production Docker image, deployed the release, checked real collections and worker restarts, and restored a new backup into an isolated directory for a second full reconciliation.

## Findings fixed

| Area | Problem found | Released behavior |
| :--- | :--- | :--- |
| CNBC price cache | A response could omit an interior cached date and add a new date without failing the old count check. | Every previously completed cached date must be present. Invalid bars and duplicate dates reject the refresh and retain the cache. |
| Independent collection | A CNBC network failure also prevented price maintenance and export refresh. | Prices and exports continue using accepted history when the source is unavailable. |
| Exports | An export failure could leave the run marked successful; direct writes could truncate files. | Export errors mark the run incomplete. Each prepared file replaces its predecessor atomically. |
| Restart retries | Repeated process interruptions could exhaust CNBC's failure retry budget. | Interrupted runs remain eligible for catch-up; completed failures consume the budget. |
| DBMF ingestion | Concurrent collection, backfill or replay could pass the duplicate check together. | A SQLite write reservation serializes duplicate detection and revision allocation. |
| Timestamp parsing | Invalid 12-hour clock values could be normalized into plausible timestamps. | Hours outside 1–12 reject the disclosure. |
| API input bounds | IDs larger than SQLite's signed integer range caused server errors. | Invalid IDs return validation errors. |
| Options interpretation | Conflicting named structures could receive a directional label; an explicit credit could be ignored when orienting a vertical. | Contradictions require explicit legs. A supported credit vertical uses the correct direction and payoff. |
| Chart selection | A failed instrument switch could leave the previous instrument's candles under the new name. | Switching instruments clears the previous chart before loading the new data. |
| API documentation | The default documentation page was blank under the app's Content Security Policy. | Swagger UI and its initialization are served locally; the strict script policy is retained. |
| Historical coverage | Four accessible issuer reports were absent from the catalog. | The catalog includes them, with an exact additional S&P 500 alias and tolerance for a wrapped clearing-corporation name. Unknown instruments still require review. |

## Remaining data limitations

1. **Holdings history is incomplete.** There is no verified holdings observation before 31 December 2021. Between that date and June 2026, the catalog lacks the September 2023, June 2024 and June 2025 quarter ends. September 2026 and intervening daily positions are also unobserved; the first saved daily report is 1 October 2026. No positions are interpolated across these gaps.
2. **Older SEC downloads remain blocked.** The three cataloged 2019/2020 filings still returned HTTP 403 from the deployment environment. They are not presented as imported data. Older issuer links that returned HTML instead of a report were rejected.
3. **167 malformed provider bars are excluded.** Counts across cached history: yen 110, euro 51, 10-year Treasury 3, 2-year Treasury 2, long Treasury 1. These remain visible chart gaps with a warning. They are not fabricated or silently filled.
4. **Five historical markets have no verified price reference.** Ultra 10-year Treasuries, ultra-long Treasuries, federal funds, Eurodollar and SOFR retain exposure history without a price chart. Collateral also has no price chart.
5. **Source agreement has limits.** This audit verifies processing against issuer/CNBC evidence and the selected price provider. It does not independently reconstruct fund accounting, establish actual trades or confirm every provider quote against an exchange feed.

### What the rejected prices mean

All 167 originally rejected bars have a close outside their reported low–high range. Some currency bars also have an open outside that range. This inconsistency is present in Yahoo's source values before yen inversion. It prevents a valid candlestick; it does **not** establish that every individual quote is false or identify the correct replacement price.

The additional ultra 10-year reference contributes four more rejected bars. The complete exclusion count is now **171**:

The dashboard now exposes each exclusion's original open, high, low and close, reporting date and specific validation failure. The JSON endpoint also preserves provider symbol, collection time and validator version. Yen evidence uses the original USD/JPY units; chart prices use the inverse. Nonfinite source values are saved as text, so evidence cannot break JSON serialization. Duplicate provider dates reject a refresh even if one duplicate is invalid. Failed refreshes retain the prior cache and its evidence.

### Independent checks and their limits

- Compared all 161 rejected FX dates with the Federal Reserve's [yen series DEXJPUS](https://fred.stlouisfed.org/series/DEXJPUS) and [euro series DEXUSEU](https://fred.stlouisfed.org/series/DEXUSEU), retrieved through FRED. **155 dates had observations**: 108 yen and 47 euro. The six missing observations fall on US holidays. These are New York noon buying rates, not a daily open/high/low/close feed.
- Yahoo closes differed from these noon rates by −2.37% to +2.14% for yen and −2.14% to +2.45% for euro. Different observation times can explain differences; these comparisons do not validate Yahoo's intraday range or justify replacing a candle.
- Retrieved complete minute-level bid data from [Dukascopy](https://www.dukascopy.com/swiss/english/marketwatch/historical/) for two sample dates: USD/JPY on 8 May 2019 and EUR/USD on 30 August 2019. Both produce internally consistent UTC-day candles, with different closes from Yahoo. Broader downloads returned HTTP 503 or timed out, so this did not establish a reliable replacement feed.
- Stooq's attempted CSV downloads returned a browser verification page. No HTML response was accepted as price data.
- The six original Treasury futures exclusions remain without an independent, verified replacement candle. CME distinguishes the day's trading range, last trade and calculated settlement. Its public historical bulletin link leads to DataMine. A settlement convention could contribute to a discrepancy, but this investigation did not prove that explanation for these six specific records. See [CME's field definitions](https://www.cmegroup.com/trading/about-settlements.html) and [historical bulletin access](https://www.cmegroup.com/market-data/daily-bulletin.html).

**No excluded candle was repaired by clamping its range, copying a nearby date or substituting a noon fixing.** A replacement source needs verified session boundaries, quote conventions and reliable historical access before being incorporated.

### References and holdings still unavailable

**SOFR:** Yahoo's `SR3=F` response identified three-month SOFR futures but returned only a current quote, without completed daily history. The market retains exposure observations and an explicit unavailable-history label.

**Eurodollar:** Yahoo's `GE=F` endpoint returned “No data found.” CME converted eligible Eurodollar contracts to SOFR in April 2023; the remaining May/June contracts expired in 2023. See [CME's conversion announcement](https://www.cmegroup.com/media-room/press-releases/2023/4/24/cme_group_completeskeymilestonesinconversionofeurodollarfutureso.html). Eurodollar history is not relabeled as SOFR, and an overnight interest rate is not substituted for a futures price.

**Older holdings and June 2025:** direct SEC document downloads remain blocked, but the [SEC bulk N-PORT datasets](https://www.sec.gov/data-research/sec-markets-data/form-n-port-data-sets) are accessible. The 2020 Q3, 2021 Q3 and 2025 Q3 files contain matching DBMF series and June reporting dates. Their fund identifiers and net assets were checked, and linked holding/derivative rows were inspected. These records have **not** been imported: the `NOTIONAL_AMOUNT` field appears to contain original amounts in inspected futures rows, and the schedules require separate treatment of cash and securities-lending collateral. For example, the June 2020 gold row contains $3,148,703.2602 plus $92,196.74 unrealized appreciation; simply importing that first field as current exposure would bypass the current-notional requirement. A reviewed adapter must reconcile these figures to a matching full schedule before publication. Availability of the bulk files does not by itself complete historical coverage.
